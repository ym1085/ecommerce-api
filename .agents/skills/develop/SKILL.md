# 대화형 멀티 에이전트 개발

메인 에이전트가 오케스트레이터를 맡고
사용자는 메인 에이전트와만 대화하게 한다.

각 단계가 끝날 때마다 반드시 멈추고
사용자 승인이나 수정 요청을 받은 뒤 다음 단계로 진행한다.

## 파이프라인

1. 🟣 설계
   `software_architect` 에이전트를 같은 이름의 `task_name`으로 호출하고
   사용자 요구사항과 제약을 전달해
   설계 지시서를 받는다.

   결과를 AGENTS.md 설명 형식으로 정리해 사용자에게 제시하고
   승인 또는 수정 요청을 기다린다.

   수정 요청이 있으면 같은 에이전트에 피드백을 전달하고
   수정된 설계를 다시 제시한다.
2. 구현
   승인된 설계를 백엔드 작업이면 🔵 `backend_developer`,
   프론트엔드 작업이면 🔴 `frontend_developer` 에이전트에 전달한다.
   각 에이전트는 같은 이름의 `task_name`으로 호출한다.

   양쪽 작업이면 수정 범위와 선행 관계를 나눠 각각 호출한다.

   생성·수정 파일과 빌드 결과를 정리해 사용자에게 제시하고
   확인을 기다린다.
3. 🟢 테스트
   승인된 설계와 구현 결과를 `test_engineer` 에이전트를
   같은 이름의 `task_name`으로 호출해 전달하고
   테스트를 작성하고 실행하게 한다.

   추가된 테스트와 실행 결과를 정리해 사용자에게 제시하고
   확인을 기다린다.
4. 🟠 검증
   전체 변경사항을 `code_reviewer` 에이전트를
   같은 이름의 `task_name`으로 호출해 전달하고
   읽기 전용으로 검증하게 한다.

   위반 사항과 수정 방향을 정리해 사용자에게 제시하고
   수정 여부는 사용자와 결정한다.

## 오케스트레이션 규칙

- 사용자 요구사항이 한 줄이어도 설계 단계부터 시작한다
- 서브에이전트에 사용자 의도, 승인된 설계, 허용된 수정 범위와
  필요한 선행 결과를 명시한다
- 서브에이전트 결과를 그대로 복사하지 않고 메인 에이전트가 검토하고 통합한다
- 단계 진행과 결과 보고에는 에이전트 설명에 지정된 역할별 원형 이모지를 동일하게 사용한다
- 사용자가 `멈춰`라고 하면 현재 상태를 보고하고 다음 단계를 실행하지 않는다
- 사용자가 `다시`라고 하면 해당 단계의 에이전트에 피드백을 전달해 재작업한다
- 사용자가 명시적으로 지시하지 않으면 커밋하지 않는다
- 사용자가 전체 자동 진행을 별도로 요청하지 않는 한
  여러 단계를 한 번에 실행하지 않는다
