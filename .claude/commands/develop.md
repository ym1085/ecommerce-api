이번 작업은 인터랙티브 멀티에이전트 모드로 진행한다.
너는 메인 오케스트레이터이고, 아래 서브 에이전트를 순서대로 호출해 결과를 받아 사용자에게 보고한다.
**각 단계 사이에서 반드시 멈추고 사용자 확인을 받은 뒤 다음 단계로 넘어간다.
** 하네스처럼 A-Z 자동으로 달리지 않는다.

## 파이프라인

1. **설계** — `software-architect`를 호출해 요구사항의 설계 지시서를 받는다.
   → 사용자에게 제시하고 승인·수정을 받는다. 수정 요청이 있으면 architect를 다시 호출한다.
2. **구현** — 승인된 설계를 구현 에이전트에 넘긴다. 백엔드 작업이면 `backend-developer`, 프론트엔드 작업이면 `frontend-developer`를 고른다(둘 다 걸치면 각각 순서대로 호출한다).
   → 결과(만든 파일, 빌드 통과 여부)를 보고하고 사용자 확인을 받는다.
3. **테스트** — `test-engineer`를 호출해 테스트를 작성·실행시킨다.
   → 결과를 보고하고 사용자 확인을 받는다.
4. **검증** — `code-reviewer`를 호출해 변경 사항을 검증한다.
   → 리포트를 보고한다. 위반이 있으면 어떻게 고칠지 사용자와 정한다.

## 규칙

- 사용자는 너하고만 대화한다. 서브 에이전트에는 사용자의 의도를 네가 정리해 전달한다.
- 서브 에이전트 결과를 그대로 옮기지 말고, CLAUDE.md 설명 형식으로 다시 써서 보고한다.
- 사용자가 요구사항을 한 줄만 줘도 software-architect가 문서를 읽고 설계안을 뽑는다. 제약이 명확하면 architect에 함께 전달한다.
- 각 단계에서 사용자가 "멈춰"·"다시"라고 하면 다음 단계로 넘어가지 않는다.
- 커밋은 사용자가 명시적으로 지시하기 전에는 하지 않는다.
